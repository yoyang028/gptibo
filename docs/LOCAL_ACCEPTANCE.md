## 本轮解决的问题

1. 本机缺少 Go、PostgreSQL 与 npm CLI：使用 D 盘便携工具，保留原主架构。npm 首次下载连接中断，复用缓存重试后安装完成；大型工具包使用分段下载与完整性核对。
2. 原后台依赖邮件验证码，本轮不接真实邮件：增加 `LOCAL_MAIL_DIR` 文件收件箱。配置仅允许回环公开来源与回环监听，且要求真实邮件关闭；原认证、TOTP、一次性验证码和会话逻辑继续生效。
3. 本地工具和数据库位于仓库中，开发服务曾无响应：限定原 HTML 扫描入口，文件监听排除 `artifacts/` 与构建目录，默认提供已构建页面预览。
4. Windows 后台 PostgreSQL 的输出管道会让带日志重定向的启动调用等待不结束：改用隐藏后台启动与实际就绪检测，重新初始化和启动通过。
5. 首版合成代理 ID 不符合原客户接口的 UUID 校验：确认空代理无业务引用后修正演示身份；客户管理随后实测通过。
6. 初次 Go 回归到 451 项时触及 300 秒总时限：保留日志，使用 600 秒限完整重跑，最终 499 项全部通过，没有通过跳过测试规避问题。

## 遗留事项及下一阶段

- 真实支付、真实供货、充值、外部退款、开票平台、通知与正式邮件没有接入或验证；匿名适配器和保留域名不能直接用于实际交易。X Premium 和依赖供货的邮件商品保留原关闭行为。
- 本轮运行并验收 Go 主后端。Cloudflare Worker 源码已参加构建与 Node 测试，但备用 D1 迁移、Wrangler 运行、云端资源与部署未实测。
- 邮件模板网页链接沿用 Go 开发公开来源 8093；浏览网页使用 5175。本地验证码读取正常，统一公开来源与正式邮件链路留到后续反向代理方案。
- 原后台通过“认证邮件是否可用”判断邮件服务状态，因此可能把本地收件箱显示为 Resend 已配置。实际 `MAIL_ENABLED=false`，没有 Resend 凭据或外发行为；本轮保持原 UI。
- 构建保留较大 JS chunk 提示；npm 12 提示两个依赖的安装脚本默认未获准，但对应平台二进制已安装，本轮测试与构建正常。没有为此改动依赖版本或自动批准额外安装脚本。
- 本地服务不注册为 Windows 自启动服务。若重启电脑或关掉运行进程，执行 `./scripts/local/start.ps1` 即可再次启动。

下一阶段优先按页面深入验收售后申请/撤回、优惠券、客户会员续费、多店铺与代理结算边界，并把本轮临时浏览器验收整理为可重复回归。之后再讨论统一本地入口和沙箱接入；真实渠道的具体协议、授权与凭据需要单独确认。
