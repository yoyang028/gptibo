# 通用店会员与邀请返券试点

本功能在现有 React + Cloudflare Worker + D1 商城内增量实现。仅对域名映射为 `store-3` 的通用店及 `plus`、`pro-5x`、`pro-20x`、`pro-25x` 四个规格开放。学术店、合作商身份及管理员登录沿用原流程；Go/PostgreSQL 后端不启用本功能。没有增加独立服务。

## 已实现规则

- Better Auth 1.7.23 管理邮箱密码、验证、会话及重置密码，使用独立会员表和密钥；Resend 发信。首次验证后即可邀请，无需先购买。游客仍可直接购买。
- 邀请链接长期有效，浏览器保存来源，创建订单时冻结服务端来源，幂等重放不能更换邀请人。会员登录、奖励核销仅接受实际通用店域名，不能通过商城范围请求头绕过。
- 新客可自选减 5 元，与普通优惠或奖励抵扣互斥；不使用 5 元仍可触发邀请奖励。购买邮箱、既有实付订单和首单唯一占用共同识别新客，充值账号邮箱作为辅助风险信息。
- 首次真实现金付款且成功交付后，邀请人获得 10 元待生效奖励。交付后观察 24 小时，无异常生效。有效期从应生效时刻起计算两个自然月，按上海时间处理月末；延迟任务不会延长有效期。
- 奖励归本人所有，按最早到期顺序使用，可以部分抵扣、跨券完全叠加或全额抵扣；140 元抵扣 138 元后剩余 2 元。采购价只决定处理路径，不限制可用优惠金额。
- 10～30 元正常处理；31～99 元增强检查，短期频繁抵扣等转人工；100 元及以上、零元或异常订单必须审核。冻结账号不能继续邀请或使用权益。
- 每笔券的发放、占用、抵扣、恢复、到期及异常处理均有只追加流水。D1 批事务、唯一约束和触发器共同防止重复发券、超扣、部分占用及审核覆盖。后台可查询会员、来源、活动订单、奖励与流水，执行审核和异常冻结。

## 订单、支付和退款

正数且不低于上游采购价的订单继续使用现有 `platform_collect`，向上游传优惠后的 `sale_amount`；真实回调、订单查询与交付结果沿用原验签和状态机。

低于采购价及零元订单可以完整使用优惠并锁定额度，进入待处理/审核，暂不创建付款入口、调用余额采购或标记付款与交付成功。人工审核通过也不会绕过这一采购限制。后续需上游确认“客户付款 + 店主账户余额补差”的接口、资金流、退款和回调契约，再补接采购路径。

原订单表有 `price_cents>0` 约束。正数活动订单仍保存实际现金应付；零元订单在该旧字段保留正数原价快照，用 `orders.member_promotion=1` 标记，由 `member_order_promotions.cash_cents=0` 提供真实应付。面向客户和活动后台的金额使用后者；任何新支付或财务接口都必须读取活动现金金额及采购/审核门禁，不能仅依据旧字段判断。

创建未付款且尚未发起上游订单的活动订单，可以由客户取消并立即释放额度。上游付款入口已建立后，本地超时不代表对方已关闭；确认上游关闭/过期后才释放。释放后出现迟到到账时转人工核对，不能重复消费或自动交付。

使用奖励的订单确认全额现金退款后恢复原券抵扣；部分退款按累计现金退款比例恢复到分，向下取整，最后全额退款补齐，重复任务不会重复恢复。不延长原券有效期。退款待确认时不提前放出额度。邀请来源订单在观察期内退款或失败时撤销待生效奖励；生效后普通退款不自动追扣。后台确认异常时，未用奖励撤销，已使用或占用的奖励保留历史并冻结权益。

## 验证与上线

本地工具环境使用 `scripts/local/env.ps1`，构建、依赖、数据库、浏览器目录和证据均位于项目 D 盘目录。主要验证入口：

```text
npm test
npm run build
npm run lint
npm run test:cloudflare:members
node scripts/sites/checkout-acceptance.mjs --domains
npm run security:scan
```

会员浏览器验收使用真实 workerd/D1 和浏览器，邮件、支付、上游均为隔离模拟，不读取生产凭据，不真实扣款。证据输出至忽略目录 `artifacts/sites/evidence/member-pilot/`。业务测试覆盖认证、重复请求、真实 D1 并发防超扣、24 小时观察、自然月到期、部分/全额退款、上游关单、迟到回调、分级审核、跨店隔离和审计失败回滚。

生产发布前应审核本任务提交，备份现有 D1，核对 `store-3` 的实际域名映射及四个规格的现有售价、成本、上游商品映射和代收开关。依次应用 `0061_member_auth.sql`、`0062_member_rewards.sql`，配置独立随机的 `MEMBER_AUTH_SECRET`（至少 32 字符），复用已配置的 Resend 服务，然后部署并设置 `MEMBERSHIP_ENABLED=true`。密钥通过 Worker secret 配置，不能写入代码或公开配置。不得在构建或启动过程中隐式迁移生产数据库。

试点开启后仍需人工核对真实验证邮件在常用邮箱的到达情况，并对一次小额真实订单核对优惠金额、付款与交付回调。上游真实行为无法由本地模拟证明。低于成本及零元订单只验收锁券、审核、取消恢复，不进行未经约定的采购。

暂停试点时将 `MEMBERSHIP_ENABLED=false`，保留已部署的订单保护代码、会员密钥、数据库及每分钟定时任务，继续处理既有锁券、退款、观察期和到期；不要回退到不识别活动订单的旧 Worker。不要删除活动表或订单标记。恢复开关不会重发奖励。

新客辅助信息不是绝对身份凭证：可解析充值账号邮箱时仅保留 HMAC，同一目标触发多次邀请会暂停审核；不保存用户提交的充值凭据。不可解析的凭据不能可靠判定不同真实客户。默认以既定低摩擦规则及人工审核控制试点风险，不增加手机号步骤。

开源参考采用 Dujiao-Next 的订单与优惠关联、OfferKit 的多笔原子核销与流水思路；没有复制其代码或引入整套服务。会员密码机制由 MIT 许可的 Better Auth 提供，其原生 D1 适配已纳入测试。
