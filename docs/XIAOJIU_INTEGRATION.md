# 小久余额采购接入

本接入适用于 Cloudflare Workers / D1 自营商品。依据小久公开的 [余额自动下单 API v2.1](https://98-xj.com/docs/cardnet-upstream-api-v2.zh-CN.md)（2026-10-14）实现 HMAC-SHA256 v2 签名，已经通过官方固定离线签名向量。

## 当前流程

客户在本站下单并向店主付款，提交付款交易号；店主核实自己的真实收款记录并在后台确认到账后，系统使用店主在小久的钱包余额采购一份对应 SKU，在原订单交付上游返回的卡密或领取内容。客户的“已付款”声明不会触发采购。

采购 API 不提供顾客付款链接、平台代收或代理分润。本站没有为此开通新的自动收款渠道。现有 GPT 代收和直充继续使用原供应商。

已有卡密的站内自动兑换属于独立的兑换站 API，需要另行申请 `xj_live_` 开头的兑换 Key；本次采购适配交付卡密，不将采购 Key 当作兑换 Key。

## 配置

1. 应用数据库迁移 `0048_xiaojiu_purchase.sql`。
2. 在“我的店铺 → 商品发布”创建商品草稿，选择 API 供货，供货来源选择“小久 · 钱包余额采购”。
3. 从小久个人中心采购 API 页面取得同一凭证的 64 位 API Key 和完整 128 位 API Secret。直接在后台密码框输入，不放入源码、聊天、环境示例或浏览器持久存储。Secret 保持原始 UTF-8 文本，不能 hex/Base64 解码。
4. 点击“读取小久余额与商品目录”，选择实际商品规格。目录读取仅调用空正文 `POST /ping` 和 `GET /products`，不会采购或扣款。也可以手填商品 ID、SKU ID。
5. 设置售价、采购参考上限、商品信息与收款说明，点击“只读检查供货目录并保存配置”。密钥对使用服务器 AES-GCM 加密存入 D1，不进入公开目录和买家订单。
6. 确认收款方式、商品和余额准备好后，运营环境显式设置 `XIAOJIU_PURCHASE_ENABLED=true`，再发布商品。未启用时只允许草稿和只读检查，不接受新采购订单。此开关也阻止未知创建结果的 POST 恢复；已知上游订单仍可查询。

Key 与 Secret 必须一起更新；旧订单保留当时的加密凭据和商品配置快照。切换凭据不会让旧订单在另一凭证的幂等空间重新下单。

## 扣款与异常处理

- 每笔本站订单固定采购一份，使用本站订单号作为 `downstream_order_no`。上游保证同一凭证、相同商家单号及相同 SKU / 数量不重复扣款。
- 创建前核对自动发货、库存、SKU 供货价与钱包余额；临近提交时再检查本站付款、售后与订单租约。
- 首次提交前保存采购已尝试标志。创建超时且未取得上游 ID 时，只重放同一个商家单号和相同业务正文，每次更换 timestamp、nonce 和签名；恢复时不因原单已经扣款导致钱包余额变低而误判。取得上游 ID 后立即保存，后续只查询该 ID。
- 验证币种 CNY、上游订单归属、商品和 SKU、数量、明细总额、退款金额及已交付内容后才交付。未知状态、退款订单和结果不明不判成功。
- **上游创建接口没有锁价或 `max_cost` 参数。采购参考上限是本站采购前的价格检查，不能保证查询与扣款之间价格不变。** 实际扣款超限时留存上游 ID 和真实成本，进入人工核对，不自动交付、退款或另开采购。
- 401 / 403 持久暂停该凭据的所有自动请求；修正凭据或 IP 白名单后，由管理员手动发起只读检查，成功的 `/ping` 才解除暂停。429 持久保存退避时间。不自动重试余额不足、库存不足或幂等冲突。
- 每个凭据限制并发调用并保留一分钟请求预算；定时采购核对串行运行。卡密不写入普通日志，只向有权访问原订单的客户展示。

## 验证边界

运行 `npm test`、`npm run build`、`npm run lint` 和 `npm run security:scan`。Node 测试使用本机模拟供货与内存 SQLite，覆盖官方签名向量、完整收款确认到发卡链路、超时同单恢复、余额不足、价格异常、凭据暂停、限流和买家隔离。

本轮通过 465 项 Node 测试以及真实本机 workerd / D1 的 12 项浏览器检查；模拟采购与清理均通过，浏览器没有打开外部付款或供货页面。已经使用本机加密保存的真实采购凭据完成上游余额与完整商品目录的只读查询；未进行真实钱包扣款、发卡或退款。真实只读查询不等于已完成正式交易，首次营业仍需独立核对实际订单。
