# ChatGPT Plus / Quefa 本地模拟对接

本轮使用 Go 主后端与 PostgreSQL，对照用户提供的 Quefa OpenAPI 1.4.1 适配 ChatGPT Plus、平台代收和自动直充。店名、品牌标识与原界面布局继续保留。

## 当前运行入口

| 用途 | 地址 |
| --- | --- |
| 本轮 Plus 联调商城 | http://127.0.0.1:5176 |
| 本轮管理后台 | http://127.0.0.1:5176/admin |
| 本地供货模拟控制台 | http://127.0.0.1:8765 |
| 本轮 API 健康检查 | http://127.0.0.1:8094/healthz |
| 本地模拟供货 API | https://127.0.0.1:8766/v1 |
| 原第一轮商城 | http://127.0.0.1:5175 |

本轮独立业务库为 `gptibo_quefa_local`；原 `gptibo_local` 保留。两者复用 D 盘 PostgreSQL 进程与工具，但业务数据、后端进程、前端构建和模拟供货状态分开。本轮数据库里的订单沿用原 `live` 状态机以验证供货适配代码，所有订单、付款、充值、退款及账务金额仍为本机模拟，不代表真实收入或交付。

模拟模式要求 API 来源和监听地址为回环 IP，数据库名称必须为上述隔离库，供货地址必须为带端口的回环 IP HTTPS。应用仅信任本地模拟器生成的私有证书，并将网络连接限制到该端点，禁用环境代理和重定向；不会更改 Windows 证书库。真实支付、其他供货渠道、真实邮件与通知继续关闭。

## 启动与登录

依赖第一轮已准备好的 Go、PostgreSQL、Node 和 PowerShell 7 工具。在项目目录执行下列命令，也可双击根目录 `local-quefa.cmd` 启动。首次启动联调环境时会构建程序并初始化独立业务库。

```powershell
& 'D:\ChatGPT\Codex\Projects\GPTibo\local-quefa.cmd' start
& 'D:\ChatGPT\Codex\Projects\GPTibo\local-quefa.cmd' status
& 'D:\ChatGPT\Codex\Projects\GPTibo\local-quefa.cmd' stop
```

`.cmd` 直接调用已存在的 D 盘 PowerShell 7，对其单个进程设置脚本执行参数，不依赖用户全局 PATH，不修改系统执行策略。停止本轮服务不会停止共享 PostgreSQL。

管理员用户名仍为 `dev-admin`。在 **5176** 后台点击获取验证码后，运行：

```powershell
& 'D:\ChatGPT\Codex\Projects\GPTibo\local-quefa.cmd' login
```

窗口显示邮箱验证码和当前 TOTP，分别填入“邮箱验证码”和“2FA 验证码”。保持登录页打开。动态码每 30 秒更新，邮箱验证码一次有效；邮件仅保存本机。两个本地站点的后台会话保存在各自数据库，建议验收时固定使用 5176，避免在同一浏览器中交替登录两个管理后台。

源码变更后重建本轮环境：

```powershell
./scripts/local/quefa.ps1 -Mode init
./scripts/local/quefa.ps1 -Mode start
```

重建会先停止本轮进程，应用迁移并以不覆盖已有配置的方式补入 Plus 演示目录；不清空业务库或模拟器状态。

## 手动体验一笔订单

1. 在 5176 商城选择 ChatGPT Plus，使用随机合成邮箱，例如 `quefa-local-demo-随机串@gmail.com` 下单。此地址仅满足原表单校验，无需对应邮箱账号。
2. 打开 8765 模拟控制台，按本站订单号找到该订单，点击“模拟付款”。模拟付款码不具备支付功能，无需扫描或转账。
3. 返回订单页，付款确认后使用控制台的“复制测试 Session”，粘贴到原表单并确认本次账号授权。只使用控制台提供的不可用演示资料。
4. 提交后显示排队或处理中。控制台可模拟“处理中”“暂停核对”“明确失败”“充值成功”。只有明确失败且查询允许重试时，原订单才重新显示输入入口。
5. 手动重试使用原付款订单和新的尝试编号；完成后在“我的订单”和管理后台查看结果。

控制台的“重复回调”用于回放最近一次通知；不会创建另一笔付款或充值。“确认待处理退款”用于将已有待核验的模拟上游退款置为完成，不代替顾客申请售后。未提交充值的订单通过原售后 API 可自动核验全额退款；涉及排队、执行或未知结果时仍保留原审核与锁定逻辑。

模拟器只保存订单、任务状态、请求摘要与安全响应，不保存收到的 Session 或 Access Token。商城后端继续按原实现加密留存本次授权资料，并保留管理取用审计。

## 本轮适配

- 下单前签名查询 `/agent-profile`，验证代理身份、active 状态、自动直充权限、商品授权与平台代收能力，再核对商品供货价。
- 按新版规则保留售价下限与成本核验，取消历史 `max_sale_price` 的上限约束。本地供货价 110 元、售价 139 元仅为合成测试值；实际授权与价格需要以后从独立沙箱或生产接口确认。
- 使用签名的 `POST /orders/{id}/payment-code`，固定空 JSON 正文及稳定幂等键；核对订单号、本地订单号、金额、币种、付款状态、码类型、有效期与允许的码地址。
- 第二次及以后手动尝试携带 `retry_confirmation=true`，同次网络重传保持原业务键和原正文；预检恢复使用同一正文构造方式。
- 新迁移 `034_recharge_paused.sql` 保存暂停标志，并同步到订单响应与前端。暂停时阻止新尝试，显示结果待核对，保留主动查询入口。
- 保留原回调验签、持久化去重、查询当前任务、版本去旧、订单权限、退款互斥与最终金额核验。退款先使用接入包仍明确支持的兼容入口。

## 正式账号的只读接入检查

用户另行授权后，可以使用正式服务端应用密钥检查当前账号权限与 Plus 供货价；这不需要先创建支付单或提交充值。此检查与模拟商城独立运行，不修改其配置，也不连接业务数据库。

1. 在 `artifacts/local/.secrets/quefa-readonly/endpoint.json` 写入供应商确认的 API 地址：`{"api_base":"https://supplier.example.invalid/v1"}`，将示例替换为实际地址。目标地址从本机文件读取，网页不能修改。
2. 双击根目录 `local-quefa-check.cmd`，或在 PowerShell 执行 `& 'D:\ChatGPT\Codex\Projects\GPTibo\local-quefa-check.cmd' start`。
3. 打开 http://127.0.0.1:8767 。在 Quefa 开放接口页创建一次性显示的凭据，把同一应用的 `partner_id`、`key_id`、`client_secret` 填入本机页面，点击“加密保存并检查”。完整密钥不要提交到聊天、源码或商城前端。
4. 页面展示实时查询结果，脱敏结果另存为 `artifacts/local/.secrets/quefa-readonly/result.json`。失败不会自动重试。再次检查可使用已保存凭据。

检查器复用 Go 后端的 HMAC 签名客户端。网络层仅允许对配置的 HTTPS 来源执行 `GET /v1/agent-profile`、`GET /v1/products` 两种请求；禁止其他方法、路径、查询参数、重定向和环境代理。它核对账号身份、active 状态、自有商城自动充值和付款码权限、平台代收、Plus 授权、可售状态、交付方式及价格一致性，不将“查询可用”当作真实交易已完成，也不能据此断定拿货资格不收费。

输入凭据使用当前 Windows 用户的 DPAPI 加密保存为 `credentials.dpapi`，绑定配置的 API 地址，未保存明文凭据或原始账户响应；不向系统证书库或全局环境写入配置。运行文件、密文和查询结果均位于被 Git 忽略的 D 盘 `artifacts/local/`。更换 Windows 用户或系统前须在自己控制的位置妥善保留原始凭据，否则密文可能无法解密。

检查器仅监听 `127.0.0.1:8767`，校验 Host、Origin 和每次启动生成的本机令牌，禁止跨站提交及嵌入。使用 `local-quefa-check.cmd stop` 停止，`status` 查看运行状态，`build` 重建已停止的检查器；停止保留加密凭据，不影响现有商城和模拟器。

此入口新增的 17 项 Go 测试及子用例、现有充值客户端的 64 项测试及子用例全部通过，失败和跳过测试均为 0；命令入口编译和 Go vet 通过。覆盖签名、两种查询的限定、权限和价格异常、跨站拒绝、DPAPI 保存与恢复、环境切换隔离及私密字段不进入结果。现有 Chromium 实测输入表单、密码遮挡与清空、保存凭据按钮、结果展示和文本转义通过，页面错误与浏览器外部请求均为 0；浏览器提交使用合成响应，不能作为真实供应商验证。受限执行策略且 PATH 无 Node/pwsh 的 Windows PowerShell x86 状态检查与重复启动通过。证据保存在 `artifacts/local/evidence/quefa-readonly/`。
