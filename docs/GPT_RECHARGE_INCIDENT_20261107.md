# GPT 自动充值凭据问题（2026-11-07）

## 已核实的故障边界

最新真实订单已付款，两个充值任务均已被上游受理后明确失败，返回 `precheck_rejected` / `account`。两次本站提交记录均为 `credential_mode=session`，因此 11 月 3 日改为 Session 模式并未解决真实充值问题。

本次通过原订单、尝试列表及两个任务的真实签名只读查询，取得上游公开说明：当前充值服务不能使用 Access Token，要求 `sessionToken` 本身或包含该字段的完整 Session JSON。上一笔订单的两次 Access Token 失败也返回同样说明；该笔后来由工作台提交的新尝试成功。

用户追加提供的新版接入包已明确区分 `credential.session` 中的 `sessionToken` 与 `credential.access_token` 中的 `accessToken`，支持根对象、`data`、`auth` 的对应字段，要求先提取再校验 131072 字符的实际令牌上限，HTTP 请求体上限为 256 KiB。旧代码仍按 32000 / 40000 限制处理，并把仅含 `accessToken` 的 JSON 当作 Session；长输入精简也未保留 `sessionToken`。

当前商城引导打开的 `/api/auth/session` 返回内容未必包含充值所需的 `sessionToken`。API 的通用 Access Token 能力不能证明该笔商品实际使用的充值通道支持这种凭据。失败与支付后重建订单无关，不应要求客户再次付款。

## 临时处置

- 临时将正式运行配置的 `RECHARGE_CHECKOUT_ENABLED` 设为 `false`，暂停各店 GPT 新下单；保留原商品价格及后台商品开关，其他供货与收款配置保持原值。
- 已付款原单保留查询和售后，未知任务仍遵守原幂等保护；不自动重提、不替客户取 Cookie，不自动退款。
- 将笼统的预检失败提示改为核对充值资料或账号条件，移除未经证实的“完成账号验证”指引，避免把通道凭据要求误说成账号验证问题。
- 真实订单号、任务号、上游原文和云端版本只记录在忽略的私有诊断文件中，公开源码不包含客户凭据或商业身份。

## 恢复销售前必须完成

1. 按已取得的新版包区分 Session Token / Access Token，并结合实际通道拒绝原因，不再把两者互换。
2. 按已核实契约修正获取说明、前后端校验和长 JSON 处理。不能把会话 Token 改名成 Access Token；不能在精简时丢掉契约要求的字段，也不能仅修改外层 `mode` 宣称完成适配。
3. 用本地模拟验证原单防重复、错误提示、凭据不入日志、售后与跨店限制。
4. 在客户明确授权和上游明确允许的前提下，验收真实自动充值结果。模拟任务成功、请求已受理或只读查询成功均不能代替真实充值完成。
5. 记录真实验收结果后恢复销售开关，保留正式版本的 Git 提交、标签和部署记录。

## 新版凭据适配

- 新提交只提取根对象、`data` 或 `auth` 中的 `sessionToken` / `session`，也支持完整原始 Session Token。仅有 `accessToken` 的 JSON 在浏览器及当前 Worker 中直接拒绝，不再创建必然被当前充值通道拒绝的新任务。
- 先提取实际令牌，再校验 131072 字符上限。Worker 与 Go 的请求体上限调整为 256 KiB；无关的长 JSON 特性数据不再随充值转发。
- 获取说明改为充值所需的会话 Cookie 值；不再把读取账号信息的 `/api/auth/session` 页面当作保证能获取 Session Token 的入口。命名 Cookie 分段按数字顺序合并，其他 Cookie 不转发。
- 原始会话值无法在本地解析邮箱时，明确显示尚未识别邮箱，要求核对获取凭据时的登录账号；本地解析不等于上游账号验证。
- 新尝试不再添加新版契约已移除的 `retry_confirmation`。旧结果未知的请求仍只在原编号及已保存摘要匹配时恢复，保留旧参数和原始字节，不自动创建替代任务。
- 浏览器提交后清空草稿，关闭表单或闲置三分钟也清除。运行日志和 D1 只保存摘要与任务状态，不保存 Session Token 原文。

适配的本地验证：623 项 Node 测试、相关 Go 充值/模拟器单元和隔离 PostgreSQL 集成测试通过；15 项本地 Chrome / Worker / D1 模拟流程通过，包括错误凭据前置拦截、300 KB 输入、精确令牌转发、原单重试、售后和实际令牌不入库。模拟验证通过不代表真实充值已完成；销售开关继续保持关闭，待真实验收。
