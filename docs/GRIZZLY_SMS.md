## 集中配置与开售

前台为 `https://shop.scholai.top/product/codex-sms`；后台为 `https://shop.scholai.top/admin?view=sms`，使用原管理员认证。应用 0049–0052 四个迁移，仅增加可浏览且不可购买的三个商品，不自动开售，不修改原 GPT 商品和支付交付配置。

在「接码管理」的遮蔽输入框保存 API Key，填写成本汇率、三个项目的售价和单次美元采购上限。使用既有 PARTNER_AUTH_SECRET 在服务端加密，前端与日志不回显密钥。旧订单保留独立的加密凭据和商品配置快照。

「只读检查余额与双池报价」只调用一次 getBalance、三个项目各两个号码池的 getPrices，不发号、不扣款。展示上次检查时间和缓存报价库存，查询失败不伪装成零。输入有改动时先保存再检查。

开售需同时满足：密钥验证通过；五分钟内检查过余额与报价；上限内有库存且余额足够；采购上限和汇率有效；售价不低于核算成本上限；支付宝商户自动收款参数齐全；PAYMENT_NOTIFY_ORIGIN 为有效 HTTPS 回调域名；PAYMENT_CHECKOUT_ENABLED=true、GRIZZLY_SMS_ENABLED=true、ORDER_TESTING_ENABLED=false。再勾选对应项目的展示和开放购买并保存。

收款私钥、支付宝验签公钥、商户参数沿用部署机密配置流程，不能写入聊天、源码或前端环境变量。现有 GPT 供应商代收不能用作灰熊订单的付款证明。普通商品编辑器、套餐价格编辑和新代理默认供货定价不接管这三个集中管理的 SMS 商品。

## 双池采购与买家流程

新订单比较美国 187 和美国（虚拟）12 的实时报价与库存，选择有货、未超单次上限的最低价池；同价优先 187。每次 getNumberV2 始终发送订单快照中的 maxPrice。

只有明确 NO_NUMBERS 才记录未取号并切换另一个池。超时、重定向、损坏或丢失响应保留原单待核对，不切池、不重买。sms_allocation_attempts 持久记录池、报价、上限和结果；数据库租约防止回调、刷新和定时任务并发采购。已知 NO_NUMBERS 后中断，可以在原订单继续尚未采购的另一池。

下单 → 订单专属付款码 → 服务端验签并核对渠道、订单和金额 → 自动发号 → 客户在所选项目发送短信 → 原单每五秒查询 → 展示和复制验证码 → 完成上游接码。发号前重查实际余额及价格；发号后先保存激活编号，再核对美国号码、国家、美元币种 840 和实际扣款上限。异常号码不交付。采购美元流水独立保存，人民币成本按快照汇率向上取整到分。

页面隐藏时暂停轮询，重新打开原订单继续。Worker 每分钟核对未结束任务，最长等待二十分钟，到期先查短信再取消。验证码先持久保存再调用完成接口，完成失败不丢码。付款不明沿用原付款单；发号不明沿用原接码单。关闭新采购不阻止已知激活的查询、完成和取消。手机号与验证码只返回给原买家、经邮箱验证找回订单的买家及管理员。

## 停止与三类资金记录

客户款进入本站收款通道；采购使用店主预充值的灰熊余额。买家停止接码时先查短信，同时到达的验证码优先交付，否则等待上游确认取消并记录时间。

上游取消不等于余额已退款。后台凭实际退款记录登记美元金额、编号及说明，不能超过已知采购扣款或重复登记。上游退回余额也不代表买家已退款：买家从原订单申请售后，使用既有独立退款审核及实际付款退款流程。

活动激活、发号不明、校验异常及占用租约的订单不能直接退款。管理员先核对灰熊账单、活动激活或客服记录，填写证据关闭任务；已知激活还需实际确认取消，已收到验证码的任务不能登记为未接码。人工关闭只解除售后限制，不执行资金退款。

## 验证与发布

使用 scripts/local/env.ps1 配置 D 盘依赖和缓存，运行 npm test、npm run build、npm run lint。设置 GPTIBO_LOCAL_VARIANT=grizzly 后启动 scripts/cloudflare/local-runtime.mjs，另一个终端运行 npm run test:cloudflare:grizzly-sms。

隔离环境 https://127.0.0.1:8791 使用真实 workerd / D1、Chrome 和签名验签；灰熊及支付网关是只允许本机访问的模拟器。没有真实付款和付费采购。测试覆盖三项目、价格、双池、缺货回退、丢失响应、并发、隔离、超时、取消与收码竞态、加密快照、异常核对及独立退款。

浏览器检查集中配置、只读检查、价格切换、付款收码与复制、停止、订单找回、亮暗主题、320/390 像素手机和减少动画。截图、结果及实际动效视频位于被 Git 忽略的 artifacts/local/evidence/sms-integration/，机密、测试数据库和产物不提交。

发布前保存 D1 Time Travel 书签，核对现有商品、机密绑定和配置；发布后验证静态资源、公开目录、原 GPT 销售与管理员权限保护。版本见 Git 提交、发布标签及私有部署记录。真实密钥、余额、库存和目标网站接收率仍需配置后核对，模拟验收不等同真实付费验证。回滚优先关闭新采购，保留迁移和历史订单，不删除接码记录。
